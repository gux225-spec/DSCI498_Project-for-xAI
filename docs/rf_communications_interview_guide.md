# RF 通信工程师访谈提纲

日期：2026-11-05。状态：访谈准备，尚无 interview findings。对象：下游 RF 通信工程师；具体职责需在开场确认。建议 15–20 分钟。

## 访谈目的与范围

了解滤波器相关解释如何支持链路测试、问题定位、器件选型或与设计团队沟通。不要预设对方直接设计微带几何，也不要预设他需要 SHAP 或 LIME。

本项目目前解释“几何 → S 参数或其标量指标”的代理模型，并未建立 EVM、BER 或接收灵敏度的端到端预测模型。访谈可以发现这些系统级需求，但不能把它们写成已实现的能力。

若对方实际不查看或使用滤波器、S 参数或器件诊断资料，他只能提供相邻领域背景，不能单独代表本项目解释的目标用户。可请他建议更直接参与前端设计、器件选型或滤波器测试的同事。

## 开场白（可直接使用）

我在做一个课程项目，用代理模型预测滤波器的频率响应，并研究怎样解释这些预测。我想先了解你实际怎样使用器件和链路测试信息，再看看这类解释能否支持某个具体决定。你不需要熟悉 SHAP 或 LIME，也不用评价微带几何设计。请尽量用不涉及保密信息的真实案例。记录时我会把你的原话和我自己的理解分开；涉及录音、署名或引用时先征求你的同意。

## 核心问题（按顺序，不需要全部追问）

### 1. 角色与接触点（2 分钟）

主问：你最近的工作主要负责哪一段链路？通常在哪些任务里接触滤波器或频率响应资料？

追问：你会直接看 S 参数、数据手册、测试曲线，还是主要看整机或链路指标？你能直接调整、替换什么？

记录：工作角色、具体任务、可用信息、可执行动作。不要仅凭职位名称判断他是否是解释的直接用户。

### 2. 一个真实的问题定位过程（3 分钟）

主问：能否讲一个最近遇到的 RF 性能异常？你最先看到什么现象，随后怎样一步步缩小原因范围？

追问：哪一步耗时最多？当时缺少什么信息？最后通过什么测量或实验确认原因？滤波器是否出现在这个过程中？

记录：触发问题 → 已看证据 → 判断 → 下一步动作 → 确认方式。不要要求对方配合一个预设为“滤波器导致”的故事。

### 3. 指标与判据（2 分钟）

主问：在你刚才的例子里，哪些指标决定是否通过或是否继续排查？为什么？

仅在回答过于笼统时追问：会不会涉及插损、带内平坦度、回波损耗、带外抑制、相位/群时延，或链路侧的灵敏度、EVM、误码率？哪些你会实际使用，哪些不属于你的职责？

记录：先记对方主动提出的指标，再记提示后认可的指标，二者不要混写。系统指标与本项目已有解释目标分别标记。

### 4. 证据如何改变行动（2 分钟）

主问：当你怀疑某个器件或频段有问题时，什么证据会让你决定复测、替换器件、调整配置，或者联系设计团队？

追问：有没有一种结论虽然看起来合理，但仍然不足以行动？还需要补什么验证？你需要向设计人员传达什么信息？

记录：具体决策、所需证据、对方无法执行的动作。把“想知道原因”和“有权限改变几何参数”分开。

### 5. 先看当前响应，再评价候选解释（4 分钟）

先展示一张项目中的 S21/S11 曲线，标明频率、参考曲线与规格边界。先问：你能从中判断什么？下一步会做什么？哪些信息缺失？

然后展示解释概念。先不介绍算法名，也不声称哪种更准确：

- A：当前预测、参考曲线、规格违反位置；这是响应信息基线。
- B：相对于固定参考的几何贡献，解释目标明确为 mask 违反量；符号表示相对参考的贡献，不是导数。
- C：当前设计附近的局部敏感度，同时注明参数单位、邻域与拟合质量；不把它包装成具体改动方案。

追问：请用自己的话解释这份信息说了什么。它改变了你的哪一步判断或行动？你不能从中推出什么？如果只有几何名称 L1/L2 而没有器件示意图，会影响使用吗？

最后才介绍 B 对应 SHAP、C 对应 LIME。若比较 B/C，轮换展示顺序；不同目标的图不能当成同一问题的算法偏好比较。

记录：理解是否正确、是否改变动作、误读点、仍需信息。不把“看起来更好”当作工作效率已经提高的证据。

### 6. 分歧与信任（2 分钟）

主问：假如一个说明给出“相对基线的最大贡献来自 L2”，另一个说明“当前位置附近改变 S2 更敏感”，你会怎样理解或处理？

追问：你会先要求什么补充信息或验证？已知参考点、局部范围、模型误差或复测结果，哪些对你有用？

注意：这两个表述是访谈用的假设场景，不是某个已验证设计的实际结果。先让受访者回答，再解释它们可能是不同问题。不能把该问当作 RF 理论考试。

### 7. 使用边界与结尾（2 分钟）

主问：在什么情况下你会参考这类模型解释？什么情况下你会坚持实测、完整链路分析，或让器件设计人员确认？

追问：如果只能保留一种信息，你会保留什么？对你而言，这个工具最可能节省哪一步，或者根本不适合哪一步？有没有更直接的潜在用户值得我联系？

记录：适用边界、失败后果、不能替代的证据。不要预设回答一定支持项目。

## 避免的问法

| 容易引导或超出角色的问题 | 更合适的问法 |
|---|---|
| 你是否觉得 SHAP 比黑箱模型更可信？ | 什么证据会让你采纳或拒绝模型给出的判断？ |
| L2 最重要，是否符合你的经验？ | 这些几何变量与你的工作有关吗？你需要什么才能判断这份解释？ |
| AI 推荐调整哪两个微带参数最有用？ | 你实际能改变什么？如果需要器件改动，你会怎样与设计团队沟通？ |
| 插损是不是你最关注的？ | 你刚才的案例里，决定通过或失败的是哪些指标？ |
| 这个解释是不是能改善 EVM？ | 这份器件层信息能支持哪一步判断？还缺什么链路信息或实验？ |

## 记录模板

每条发现分开保存：

- Participant / role / date：待填写。
- 真实任务与场景：待填写。
- 原话或明确标为转述的回答：待填写。
- 当前使用的证据和具体行动：待填写。
- 我的解释：待填写。
- 对本项目目标或呈现的影响：待填写。
- 证据边界 / 反例 / 后续问题：待填写。

访谈后可用“1 位下游 RF 工程师在其工作流中指出……”；不要写成“RF 工程师普遍需要……”。若没有访谈，slide 只能写“计划验证的需求”，不能填入预期答案冒充 finding。

## 从回答到设计决定的映射（均为待验证假设）

| 若访谈发现…… | 可以考虑的项目调整 | 尚不能宣称…… |
|---|---|---|
| 对方按频段与规格定位问题 | 把频段、规格裕量和目标名称放在归因图前面 | 已提高定位效率 |
| 对方不能调整几何 | 将几何归因用于设计反馈或沟通，核实是否有用 | 对方会直接执行反事实几何调谐 |
| 对方需要小范围调节方向 | 单独展示 LIME 斜率/有限差分与适用邻域 | SHAP 正号就是增大参数会更差 |
| 对方主要关注 EVM/BER | 记录下游需求与模型能力缺口 | S 参数归因已解释 EVM/BER |
| 对方不使用滤波器解释 | 调整目标用户招募 | 已完成目标用户可用性验证 |

## 可作为 stakeholder evidence 的 practitioner sources

以下是厂商应用资料，不是受访者发现。它们用于建立工作流假设，不用于证明目标用户接受 XAI。

1. Rohde & Schwarz，Paul Denisowski，Understanding error vector magnitude：说明频率响应、噪声、非线性、相位与配置等都可能影响 EVM。因此访谈应问实际排查过程，不能先把链路异常归因于滤波器。
   https://www.rohde-schwarz.com/us/products/test-and-measurement/analyzers/signal-and-spectrum-analyzers/understanding-error-vector-magnitude_258370.html

2. Analog Devices，Brannon / Man / Gupta，AN-1354：在一个 AD9371 LTE 接收机案例中讨论 RF 滤波、带外干扰、发射噪声与系统接收性能。支持从链路任务理解滤波器需求；具体器件、频段和拓扑不能直接外推至本项目。
   https://www.analog.com/en/resources/app-notes/an-1354.html
